# Captrain design

Author: Nitish

Source of truth: PLAN.md with Nitish's 14 October reference and requested screenshot workflow corrections below. Windows 11 x64, Tauri 2, React and TypeScript, Rust native ownership. Screenshots, saved web links and local video recording.

## User experience

Launch as a right-edge 16 × 72 logical-pixel hit area containing a 6 × 56 bar. Hover grows the bar inward, never opens it. Click opens a warm-white 540 × 740 shelf, clamped to the monitor work area. Left/right edge and display are settings. Match the supplied reference's compact utility layout: segmented All/Captures/Exports header, list/grid toolbar, pastel tabbed folders with counts, filename rows and an anchored capture/folder footer. Segoe UI Variable/Segoe UI, charcoal text, rounded shelf, restrained motion with reduced-motion support.

Drag the collapsed edge bar to any height on either the left or right edge of any connected display; it stays snapped to the nearest side edge of the display under the pointer. Save the display, edge and normalized vertical position on release. A click still opens the shelf; arrow keys on the focused bar adjust its height. Clamp the bar and opened shelf to the monitor work area, account for each monitor's DPI and negative coordinates, and fall back to the primary display if its saved display is disconnected. Existing settings retain centered placement.

The tray menu includes a persisted checked ?Shortcuts only (hide edge bar)? option. It hides the collapsed bar while keeping all existing global shortcuts active. Successful screenshots, links and finalized recordings show a compact non-activating Captrain desktop toast instead of opening the library, including when capture follows a manual shelf open. Errors and export warnings remain visible in the toast. The toast shares the native three-second dismissal timer, pauses on hover, and offers Open shelf and Dismiss. Tray Open shelf, tray left-click and the configured shelf shortcut still open the full library; recording setup and controls remain accessible through the video shortcut or tray. Disabling the option restores the saved bar position. Capture cancellation retains the previous mode; existing shortcut registrations and library contents are unchanged.

Library searches kind, localized date and filename with pagination and folder/export filters. Organizational folders support create, rename, delete without deleting captures, and moving captures. The footer's folder selects the destination for new captures; Settings separately selects an optional Windows directory for automatic PNG copies and exposes the current storage location. Originals remain in the private library, so disconnecting an output drive does not destroy history. Existing captures are never moved implicitly. Export copies survive deleting a library capture.

Clicking a thumbnail opens a separate owner-modal native viewer over the shelf, with previous/next navigation across the filtered library, fit/1:1/zoom controls, wheel zoom, pointer pan, Copy, Save as, Move to folder and confirmed Delete. Escape closes it. The parent shelf is disabled and held open until viewer close. Capture rows offer the same appropriate actions through a custom right-click menu with keyboard support; editable text retains its text-editing menu. No browser page menu on the app surface.

Instant capture is an explicit persisted setting, enabled by default. The main Capture button immediately executes the selected Region/Window/Screen action; its separate arrow changes type. Region immediately opens selection; direct Window captures the last external foreground window, remembered before shelf activation by a native foreground event hook. Disabling instant mode presents the action menu/window picker. A committed thumbnail animates into the shelf and settles into its row; reduced motion skips the flight. Settings retain transactional shortcut-conflict feedback. No Record placeholders, automatic clipboard replacement, accounts or remote content.

Save the active page in Chrome, Edge or Brave on Windows with Ctrl+Alt+4 (editable in Shortcuts), or Link in the capture dropdown using the last external browser window. Link is an immediate menu action with its own shortcut, alongside Region/Window/Screen; no separate footer link icon. Saved-link rows show the domain above the full URL and saved time, with one link tile and an open-in-browser indicator; only exported links carry a save badge. Native Windows UI Automation reads the visible document URL, falling back to an unambiguous address-bar URL; it never focuses controls, sends keystrokes, changes the clipboard, or reads page content. Only complete HTTP/HTTPS URLs without embedded credentials are accepted. Unsupported, inaccessible and ambiguous pages report an error without creating an item. Each saved link commits a local .url file and metadata atomically, appears under All and applicable folders/Exports, supports URL search, opens in the default browser and shares Copy, Save as, Move and Delete. Captures contains screenshots and recordings; image-viewer navigation contains screenshots only. Automatic disk copies also support .url files; failures retain the protected original. Existing screenshot history and custom shortcuts migrate without replacement.

Link also saves the active filesystem folder in Windows File Explorer with the existing Ctrl+Alt+4 shortcut or Link menu action. Shell automation resolves the foreground Explorer window and active tab without changing focus or clipboard contents; Home, This PC and ambiguous tabs report an error. Drive and UNC network paths are stored as validated file URLs in the existing link-item format, displayed and copied as Windows paths, and opened in Explorer. Folder links share organizational folders, search, export and deletion behavior with web links. Export saves a .url shortcut, never copies or deletes the target folder; an offline target does not invalidate saved history.

Both web and Windows folder links offer Rename in their context menu. A separate optional display title (1 to 120 characters) persists atomically and is searchable; the full target remains visible under the name. Renaming changes only Captrain's display title, preserving the URL/path, private shortcut filename and previously exported copies. Legacy items without a title retain their previous automatic label.

Settings > General offers System, Light and Dark appearance, with System retaining the previous Windows-following behavior. The persisted choice applies to the shelf and image viewer and is cached for first paint. Start with Windows is off until enabled; its switch reads and writes Captrain's quoted executable entry in the current user's Windows Run key, requires no administrator rights and starts the existing shelf bar at sign-in. Enable it from the installed copy. Windows Startup settings can independently disable startup.

## Video recording

The capture dropdown's Video action or Ctrl+Alt+5 (editable in Shortcuts) opens setup for Screen, Window or Region; no separate footer video button. Both capture menus use the short labels Region, Window, Screen, Video and Link, with Instant for the capture toggle. Menus containing checks reserve the same check column for every row, keeping labels aligned and shortcut hints right-aligned. Existing four- and five-action shortcut settings gain Video without replacing custom bindings; an unused fallback is chosen if Ctrl+Alt+5 is taken. The shortcut opens existing controls during recording and never starts devices directly. Screen-only is the default: system audio off, microphone off and webcam off. Optional devices are opened only after an explicit recording start with that source enabled. Source/device enumeration never starts capture. Region reuses the existing physical-pixel selector; Window uses native window capture, with no desktop-crop fallback. Choose 30/60 fps, Standard/High/Maximum bitrate presets, original/1080p/720p output without upscaling, cursor visibility and an optional three-second countdown. High quality and 60 fps are the initial defaults.

Optional microphone selection and system loopback audio mix into one AAC stereo track. The optional camera is baked into the video as a square inset, with four corner positions and three sizes. Circular masking and mirroring are not implemented in this version. No continuous preview. During capture a red shelf bar remains available; opening it reveals elapsed time excluding pauses, explicit device indicators, Pause/Resume and Stop. The shelf is excluded from capture. Capture actions, viewer opening, updater installation and tray Exit share recording exclusion; stop before exiting or updating. Completed MP4s appear under All/Captures and their destination folder, open in the default Windows video player, and support Save as, Move and confirmed Delete. Video clipboard copy is omitted.

Rust owns the recording transaction and process lifetime. A Windows x64 .NET Framework 4.8 helper uses pinned MIT-licensed ScreenRecorderLib 7.0.1: Windows Graphics Capture, D3D11 texture composition and scaling, WASAPI audio and Media Foundation H.264/MP4 encoding. The helper exists only while enumerating devices or recording. React receives configuration and bounded status messages, never video frames. The app does not loop the screenshot CPU/PNG path for recording. The helper requests hardware encoding and retains encoder throttling. **Actual hardware transform selection is not verified; Windows may choose software.** Frame pacing, memory, encoder choice, text quality, HDR/SDR behavior, camera/audio synchronization and sustained 1080p60/1440p60/4K performance remain hardware acceptance checks. No zero-drop or universal no-lag guarantee is claimed.

Recordings write fragmented MP4 directly into the private recordings directory. Only successful finalization commits library metadata. Failure, timeout, crash or metadata-write failure retains partial/unindexed files and reports their location; startup reports unindexed recordings without deleting or silently importing them. Fragmented files may still require manual repair after a crash. Export streams to a temporary file and atomically replaces the chosen destination; automatic exports use unique exclusive names. Neither export path buffers the entire video. All playback/export/delete requests resolve owned IDs in Rust.

The installer build first builds the helper and bundles its pinned recorder dependency, license and app-local Microsoft VC runtime DLLs. The helper uses the Windows-provided .NET Framework 4.8; no separate .NET runtime is shipped. Source development requires `npm run recorder:build` before recording. App/installer builds are run by Nitish or existing release CI, never implicitly by the agent.

## Brand identity

Keep the Captrain name and existing utility style. The canonical mark is `public/captrain.svg`: a flat muted-blue (#3d5f94) rounded cube silhouette with a bold warm-white (#fcfaf7) C angled onto its right face, matching Nitish's approved rounded-cube C image, preserving its soft curved letter terminals. Keep the background transparent; no gradients, outlines or extra decoration. The shelf's brand button retains Show everything; Settings pairs the mark with the Captrain name. Use the same mark for the favicon, native tray, executable and installer. Generate native sizes with `npx tauri icon public/captrain.svg --output src-tauri/icons`; retain only the Windows PNG/ICO assets. Preserve the application identifier and storage paths.

## Native invariants

Rust owns the shelf state machine and its single replaceable dismissal deadline, native placement/focus, capture transaction, shortcuts and serialized persistence. This consolidates dismissal with native focus and capture events rather than duplicating timers in React. Pure Rust state tests cover the same deterministic transition contract proposed for src/shelf/state.ts in PLAN.md. Temporary reveal uses show-without-activation and arms dismissal after frontend ready; manual open explicitly activates. Hover and holds pause dismissal; stale deadlines cannot close newer/manual state. Native deactivation collapses manual mode. Capture cancellation restores prior mode; capture completion never promotes temporary to manual. Tight native window bounds leave no large invisible click-catching surface.

One native transaction freezes a clean display after hiding app surfaces and synchronizing the compositor. Region selection uses physical pixels over the frozen display. Window selection uses eligible window rectangles and Windows Graphics Capture of the selected native window, never a desktop crop. PNGs and thumbnails commit before the atomic index replacement and notification. All file commands accept owned capture IDs. The frontend receives data URLs only for the visible page/preview. Export uses a native Save dialog and preserves the original.

Owned originals, thumbnails, metadata and settings stay in per-user local app data. Optional auto-saved copies use unique names and exclusive file creation in the native-selected Windows directory. A failed auto-save reports the error while retaining the committed library capture. The index migrates legacy flat history on its next mutation and atomically persists folder metadata and memberships together. Malformed metadata/settings are preserved and reported. No silent purge. Shortcut changes register new bindings transactionally and retain old bindings on conflict. Single-instance and tray reopen/exit are required.

## GitHub releases and updates

Match FB_rea's Windows release flow: every push to main/master builds a Windows x64 NSIS installer, assigns the base patch plus GitHub run number, and publishes a GitHub Release with generated notes. Upload the installer, signature and latest.json to a draft; validate the updater assets before publishing. Keep npm, Tauri, Cargo and both lockfile package versions synchronized in CI without committing version bumps.

Installed release apps check the public NitishMPD/Captrain GitHub feed 10 seconds after launch and every six hours. Settings provide status, release notes, progress, manual check, explicit download and explicit restart/install; the shelf shows an available/ready update notice. Development never fetches updates. Tauri's updater owns HTTPS, version comparison and signature verification. Only the shelf may invoke update commands. Installation shares capture/viewer exclusion and waits for active persistence; captures and local data survive application replacement. Store the signing private key outside the checkout and in the GitHub Actions secret, with only its public key in app configuration. No Windows Authenticode certificate is configured.
